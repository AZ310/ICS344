## Project Overview

This project uses the **DVSA (Damn Vulnerable Serverless Application)** — an intentionally vulnerable AWS-based application developed by OWASP — to practice identifying, exploiting, and remediating real-world serverless security vulnerabilities.

Each lesson involves:
1. Understanding the vulnerability and its root cause
2. Reproducing the exploit in our live AWS environment
3. Applying and verifying a fix

**Live DVSA URL:**  
`http://dvsa-website-006127064090-us-east-1.s3-website.us-east-1.amazonaws.com`

## Vulnerabilities Covered

### Lesson 1 — Event Injection
The `node-serialize` library deserializes attacker-controlled JSON and executes embedded JavaScript via the `_$$ND_FUNC$$_` marker. We exploited this to run arbitrary code inside the Lambda runtime and proved it via CloudWatch logs.

**Fix:** Replaced `node-serialize` with `JSON.parse()` and added an action allowlist.

---

### Lesson 2 — Broken Authentication (JWT Forgery)
JWT tokens were decoded but never signature-verified. By base64-decoding the payload, swapping the `username` field with another user's ID, and re-encoding — the API accepted the forged token and returned the victim's orders.

**Fix:** Integrated Cognito JWKS endpoint for full RS256 signature verification before trusting any JWT claims.

---

### Lesson 3 — Sensitive Information Disclosure (Direct Lambda Invocation)
`DVSA-ADMIN-GET-RECEIPT` relies solely on API Gateway for authorization. Invoking it directly via the AWS CLI bypasses all auth checks and returns a pre-signed S3 URL granting access to any user's private receipt.

**Fix:** Added an internal `isAdmin` check inside the Lambda handler + restricted the Lambda resource policy to only allow invocations from API Gateway.

---

### Lesson 4 — Broken Access Control (Admin Function JWT Bypass)
The `DVSA-ADMIN-UPDATE-ORDERS` Lambda split the JWT on `.` and base64-decoded the payload directly without verifying the signature. This allowed any authenticated user to forge an admin token and call restricted admin operations.

**Fix:** Applied Cognito JWKS JWT verification and an explicit `custom:isAdmin` claim check before executing any admin logic.

---

### Lesson 5 — Insecure Cloud Configuration (S3 Public Access)
The `dvsa-receipts-bucket` had **Block All Public Access** disabled. This meant any bucket policy or ACL misconfiguration could silently expose private receipt objects to the public internet.

**Fix:** Enabled Block All Public Access on the bucket. Receipts remain accessible only through pre-signed URLs generated by authorized Lambda functions.

---

### Lesson 9 — Vulnerable Dependencies
Closely linked to Lesson 1. The root cause of the event injection is the use of `node-serialize`, an unmaintained package with a known deserialization RCE vulnerability. The same fix (replacing it with `JSON.parse`) eliminates this dependency risk.

---

### Lesson 10 — Unhandled Exceptions (Stack Trace Leakage)
Calling `.lower()` on a boolean `isAdmin` field raises an unhandled `AttributeError` in Python. Because the Lambda had no `try/except` block, the full stack trace — including internal file paths and variable names — was returned directly to the client.

**Fix:** Added safe type handling for the `isAdmin` field, wrapped the handler in `try/except`, and ensured only generic error messages are returned to clients while full details are logged to CloudWatch.
